01MFT scanning

Reads the table of contents, not the book.

Every NTFS volume keeps a Master File Table: one record per file and folder. Strata reads it straight from the volume device instead of opening millions of folders one by one.

  • Raw, unbuffered reads. Opens \\.\C: with sector-aligned buffers and follows the $MFT runlist from record 0, so a fragmented table is read fragment by fragment in 8 MiB chunks.
  • Parallel parsing. One I/O thread feeds a bounded channel; a worker pool applies update-sequence fixups, parses attributes and merges extension records.
  • Exact sizes. Hardlinks count once, compressed, sparse and CompactOS files count the clusters they use, cloud placeholders count what is local, and alternate streams and folder indexes are included.
  • Hardened. Torn and corrupt records are counted and skipped. The parser is fuzzed and never panics on malformed input.
  • A fallback that agrees. Without administrator rights, or on ReFS, FAT, exFAT and network shares, a parallel standard scanner emits the same records, without ever recalling cloud files.

02Live index

Scan once. Stay current.

NTFS records every change in its USN change journal. Strata follows it and patches its in-memory index in place, so the map you are looking at is the disk as it is now.

  • Deltas, not rescans. Journal records are coalesced per tick, the changed MFT records are re-read, and only the affected entries and their parent folders are updated.
  • Silent when idle. Reads block until something changes, so an idle volume costs no CPU: {{bench.idle}} in the benchmark.
  • Opens at once. Each volume’s index is cached with per-section checksums and caught up from the journal at the next launch; any mismatch falls back to a scan.
  • Honest about gaps. A wrapped or recreated journal shows a notice and can trigger a rescan. Volumes indexed by the standard scanner are watched folder by folder.
  • Compact. A struct-of-arrays index uses {{bench.memory}} of memory per entry, plus its name.

03Explains every file

What it is, who made it, and what deleting it means.

{{rules.count}} built-in rules in {{rules.packs}} packs classify every file and folder into one of {{rules.categories}} categories, name the app that owns it among {{rules.apps}} they recognise, and assign a safety tier.

  • Four safety tiers. Safe regenerates by itself, probably is likely junk, careful is your data or a large re-download, and never has no delete action anywhere.
  • Owner attribution. Installed-program registry keys (machine, 32-bit and per user), AppX packages, rule labels and folder names, each with a confidence and its evidence.
  • “Why is this X?” Every classification shows the rule that won, the folder it was inherited from, and every candidate that was considered.
  • Yours to extend. Add TOML packs to your rules folder to cover your own tools. A user rule can tighten any tier, but it can never relax a built-in never.

04Safe cleanup

Every layer fails closed.

Deletion is the only destructive thing Strata does, so it passes through independent checks, each able to stop it, and lands somewhere you can take it back from.

  • A never-delete list in code. Volume roots, the Windows folder, Program Files, every profile root, known-folder roots, boot and paging files, NTFS metadata and more, enforced by the app and again by the elevated helper.
  • Every spelling checked. \\?\ and \??\ prefixes, UNC and admin shares, volume GUID paths, mount points, trailing dots and 8.3 short names all resolve to the same protected location.
  • Re-verified by file id. Right before acting, the item is opened without following links, and its volume serial, file id, size and modification time must still match the scan.
  • Recycle Bin by default. The undo log is written before anything is touched, and a restore puts files back without ever overwriting.
  • Locks, named. Restart Manager shows which program holds a file. Closing it is a polite request after you agree, never a kill.

05Search

Results before you finish typing.

One parallel pass over every name on the volume, with filters checked before any name work. Results stream in as each chunk finishes, and each keystroke cancels the query before it.

06History and snapshots

See what grew, and when.

Each scan can store a snapshot of folder sizes. Compare any two and Strata lists what grew, what shrank and what appeared, folder by folder.

  • Small by design. Snapshots keep aggregate sizes of folders above a threshold (16 MB by default), about 12 bytes per folder, never individual files.
  • Self-pruning. Thinned to one a week after 30 days and removed after 90 days by default; both limits are in Settings.
  • Kept apart. History lives in its own database, so resetting it never touches your settings or the undo log that restores depend on.

07Duplicates

Real copies only. Nothing downloaded.

Files are narrowed down in stages, so most candidates are ruled out without reading a byte, and only true byte-for-byte copies reach you.

  • Three stages. Group by size, then hash the first, middle and last 64 KiB, then hash the whole file. Hashes are cached, so a rerun reads {{bench.dupes-rerun}} from disk.
  • Hardlinks are one file. Paths that share a file record are never reported as copies of each other.
  • Cloud files stay in the cloud. Placeholders are never opened, and every open forbids recalling cloud content.
  • Can’t lose the last copy. A selection can never include every copy in a group; Strata suggests which to keep and says why, then re-checks before deleting through the same safe cleanup.

08Activity · opt-in

Which program is filling your disk, right now.

Turn on activity tracking and Strata records which programs write, create and delete files, per folder and per hour, plus the last program that wrote each path.

  • Off by default. It needs administrator rights and runs inside the elevated helper as one kernel trace session.
  • Light. Tracing stays under a CPU cap (2% by default); above it, Strata samples writes and scales them, and suggests turning tracking off.
  • Accurate attribution. Processes are keyed by id and start time, so a reused process id is never blamed for another program’s writes.
  • Local and temporary. Activity data stays in the history database and is deleted after 30 days by default, or whenever you clear it.
